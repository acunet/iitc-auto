## Three things that had to be fixed before upstream could be built on this machine

All three are done and (where possible) already committed to the repo:

1. **Upstream's `mobile/gradlew` is too old.** The wrapper script (2015) relies on `cygpath` to convert `CLASSPATH` from MSYS style to Windows. On this git-bash host that conversion never happens, so `java` receives `-classpath /c/Users/...` → `ClassNotFoundException: org.gradle.wrapper.GradleWrapperMain`.
   *Fix:* `gradlew`, `gradlew.bat`, and `gradle/wrapper/gradle-wrapper.jar` were replaced with the ones generated by Gradle 8.13 (taken from the `probe/` project).
2. **`mobile/keystore/debug.keystore` isn't in the upstream repo** (gitignored), even though `mobile/app/build.gradle` points at `file("../keystore/debug.keystore")` — meaning relative to `mobile/keystore/`, **not** the repo root.
   *Fix:* generated with `keytool` (alias `androiddebugkey`, storepass/keypass `android`).
3. **`mobile/keystore.properties` must exist** — the build script evaluates `signingConfigs.release` even though we only build debug, and the non-CI branch reads that file during configuration. Without it: `C:\...\mobile\keystore.properties (The system cannot find the file specified)` even when the target is debug.
   *Fix:* created a local file (gitignored) holding the absolute path to the debug keystore above.

Points 2–3 **do not go into git** (as they should not); they are recorded here so they can be reproduced on another machine.
