# Evidence & notes: IITC running on the car screen, and the Android Auto path traps

Date: 2026-10-25

## 1. Big bug found and fixed: fork APK without IITC assets

The IITC Mobile fork APK produced by `./gradlew assembleDebug` **has no `assets/` folder** — so the
IITC userscript isn't there at all and the app hangs on the splash screen forever.
In logcat the symptom is just a pile of warnings from
`IITC_FileManager.getAssetFile` → `getScript` → `getResponse` → `IITC_WebViewClient.shouldInterceptRequest`.

Those assets are generated by the upstream build script, not by Gradle:

```bash
npm install                 # lightningcss CLI and friends (required; without this build.py refuses)
python build.py mobile      # creates assets/total-conversion-build.user.js + assets/plugins/*
```

Result: `mobile/app/src/main/assets/total-conversion-build.user.js` (1.5 MB) + a `plugins` folder
(~50 user.js files), and `build.py mobile` also runs `assembleDebug`.

`assets/` and `node_modules/` have been added to `.gitignore` (both are generated output).

## 2. DHU (virtual head unit) is DEAD for the user's phone's Android Auto version

Android Auto **17.8.663884** on the user's phone **no longer has a "head unit server"**: string
searches in the APK's `resources.arsc` and `classes*.dex` return 0 matches for `head unit server`.
Without that server, DHU 2.0 can't connect over the ADB tunnel (`Waiting for phone...` in the DHU
window), and USB/AOA mode (`-u`) also fails on this machine (`Device 'MSI MYSTIC LIGHT' does not support AOAP`,
`Couldn't find/access compatible USB device`).

Consequence: **the Android Auto projection test can only be done in the car** (or by downgrading AA —
but older Android Auto versions don't support parked apps, so the trade-off isn't worth it).

## 3. Parked app path: PROVEN up to the point where the intel page loads

After the `android.intent.category.CAR_LAUNCHER` category was added to the fork's main activity
(see `parked-app-plan.md`), the app was run on the AAOS emulator:

- IITC Mobile appears and runs **fullscreen** in the car screen layout (1408x792).
- IITC intro → location permission dialog → `IITC_Mobile` activity (WebView).
- The WebView successfully loads **intel.ingress.com** and shows its gateway page:
  `Welcome to Ingress.` / `Sign in` / `Learn More` / `Niantic Labs` — with the IITC toolbar
  (hamburger, search, GPS, layer, fullscreen, overflow) above it.

Evidence: `docs/notes/img/iitc-on-car-screen-intro.png`, `docs/notes/img/iitc-intel-on-car-screen.png`

Which means: once the user logs into their Ingress account, **the full IITC map will show on the car
screen** (proven on AAOS; on Android Auto projection it still needs confirming in the Jaecoo,
including whether the AA host shows this app with a "P" badge).
