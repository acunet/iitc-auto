# Proof of F2 verification with real portal data

Device: SM-F731B (Galaxy Z Flip 5), Android 16, app `org.exarhteam.iitc_mobile.debug` ("IITC Auto"),
logged into Ingress with a dummy account.
Date: 2026-10-25

## 1. Userscript installed automatically by the app

```
$ adb logcat -d -s iitcm | grep 'bridge:'
bridge: userscript Android Auto disuntik ke WebView
```

## 2. State inside the WebView (via Chrome DevTools Protocol)

```
$ python scripts/cdp-bridge-test.py --probe
target: Ingress Intel Map | https://intel.ingress.com/?vp=m
{
  "url": "https://intel.ingress.com/?vp=m",
  "bridgeInstalled": true,
  "nativeBridge": true,
  "iitcLoaded": true,
  "portalCount": 237,
  "hasMap": true,
  "lastSentMs": 1792900510513
}
```

## 3. Real payload received by the native side

```
$ python scripts/cdp-bridge-test.py --trigger
dipicu; portal di window.portals: 237

$ adb logcat -d -s iitcm | grep 'bridge:'
bridge: payload portal diterima (237 portal, 26422 char)
```

Final counts over the log buffer: **payloads accepted: 3, payloads rejected: 0**.

That means the following chain is proven live with real portal data:

```
WebView IITC (Ingress login, 237 portals in the viewport)
  → iitc-auto-bridge.js          (mapDataRefreshEnd hook + throttle)
  → app.sendPortals(json)        (JavascriptInterface)
  → IITC_JSInterface.sendPortals (source validation: intel.ingress.com)
  → PortalBridge.accept          (256 KB limit, v1 parser)
  → PortalSnapshot               (237 Portals parsed, 0 rejected)
  → PortalMapScreen              (PlaceListMapTemplate — rendering already proven on the AAOS emulator)
```
